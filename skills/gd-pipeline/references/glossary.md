# Glossary for first-time developers

Explain a term in plain words the first time it appears in a conversation. Keep the English term; add the explanation in brackets in the user's language.

| Term | Plain meaning |
|---|---|
| Core loop | The few actions the player repeats all game long (e.g. prepare → fight → collect → prepare) |
| Meta loop | What changes across many loops or sessions (unlocks, story, upgrades) |
| Pillar | A short rule saying what the game must always feel like; used to say no to features |
| Player fantasy | Who the player gets to be and what it feels like |
| Hook | The one sentence (or 5 seconds of video) that makes a stranger understand and want the game |
| Prototype | A quick, ugly, throwaway version built only to test whether something is fun |
| Greybox | A prototype made of plain shapes, no real art |
| Playtest | Watching someone play to learn what works; you observe, you do not explain |
| Blind tester | Someone who has never seen the game and gets no help |
| Go/no-go criteria | Pass/fail rules written before a test, so results cannot be argued away afterwards |
| Gate | The checklist that must be true before moving to the next stage |
| Pivot | Keeping what works but changing the core of the game |
| Scope | How much game there is to build: systems, levels, characters, lines, assets |
| Scope creep | Scope growing without anyone deciding it should |
| Feature creep | Adding features mid-way that were not planned |
| Cut list | Things decided in advance to drop if time runs short |
| Pre-production | Planning and testing phase before building the full game |
| Vertical slice | One small part of the game finished to final quality, to show what the full game will be and to measure cost |
| Horizontal slice | All systems roughly present but nothing finished; not a vertical slice |
| Tech spike | A short experiment to answer one technical question |
| Production | The long phase of building all the content |
| Milestone | A dated checkpoint with a playable build |
| Feature lock / content lock | No new features / no new content after this point, only fixing and polishing |
| Alpha | Every feature works; content may be placeholder |
| Beta | Everything is in; only fixing and polishing remain |
| Release candidate (RC) | A build you would ship if no new blocker is found |
| Placeholder | Temporary art, text or sound standing in for the final version |
| Polish | Small improvements to feel, clarity and presentation |
| Balance | Tuning numbers so choices are fair and challenge feels right |
| FTUE | First-time user experience: the first minutes, including the tutorial |
| UX | How easy the game is to understand and control |
| Store page / Coming Soon page | The game's page on a store before release, where people can wishlist |
| Capsule | The main store image; it must read at thumbnail size |
| Wishlist | A player asking the store to notify them at release; the main pre-launch demand signal |
| Next Fest / festival | A store event where unreleased games show demos to a large audience |
| Demo | A free, short, polished playable part of the game for the public |
| Press kit | A page with description, screenshots, trailer, logos and facts for journalists and creators |
| Publisher | A company that funds and/or markets the game in exchange for a revenue share |
| Postmortem | A written review after launch: what went right, wrong, and what to repeat |
| Stage debt | Work done ahead of its stage, which may need redoing if an earlier gate changes the design |
